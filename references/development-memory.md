# Длительная разработка и экономия контекста

Расширение подключается отдельно к существующей памяти 3.0. Схемы STATE/MISSION не меняются. Каталог `.project-master/private/development` содержит private registry, checkpoint и производный SQLite index. Не публикуй его. Архитектура, требования, решения и код остаются исходными документами.

## Подключение

Из установленного skill, с явным корнем:

```bash
python3 scripts/development_memory.py --root PROJECT enable
python3 scripts/development_memory.py --root PROJECT enable --apply
python3 scripts/development_memory.py --root PROJECT register architecture .project-master/ARCHITECTURE.md --kind architecture --summary 'Ответственность модулей и обязательные инварианты'
python3 scripts/development_memory.py --root PROJECT checkpoint
python3 scripts/recover.py --root PROJECT --compact --budget 3000
```

Первый вызов показывает план. Apply сохраняет копии STATE/CURRENT_STATE и создает отдельное хранилище, не меняя прежних approvals. Повторное enable не перезаписывает память. При существующей неполной установке диагностируй ее, не удаляй память. Для возврата достаточно перестать использовать расширение; исходные документы сохранены.

После подключения закрепи в существующих AGENTS.md проекта правило: при новом чате/compaction сначала `python3 <SKILL_ROOT>/scripts/recover.py --root <PROJECT_ROOT> --compact --budget 3000`, затем прочитать только актуальные источники для задачи. Не перезаписывай другие инструкции. Чат без доступа к проекту не получает автоматической памяти.

## Рабочий цикл

1. Восстанови цель, ограничения, next_action, статус проверок и checkpoint. При `workspace_changed` сравни ветку и незавершенную работу; при stale источнике перечитай только соответствующий документ и обнови summary через register. Никогда не регистрируй старую сводку под новым hash без чтения.
2. Перед изменением найди контракт и архитектурные инварианты, проверь связанные решения/тесты. `neighbors ID --limit 12` возвращает только один переход по явным актуальным связям. Дальнейший переход — отдельный осмысленный запрос, не обход всего графа.
3. После значимого результата обнови существующие STATE/MISSION обычными скриптами. В отдельном handoff-документе укажи незавершенную работу, измененные файлы, подтвержденные проверки, остаточные ошибки и следующий проверяемый шаг. Зарегистрируй его и сделай checkpoint. Перед передачей и паузой checkpoint обязателен. Если сессия оборвалась раньше, состояние считается неполным, а не успешным.
4. После изменения архитектуры/решения обнови исходный документ, затем его summary и индекс. Checkpoint хранит версии исходных stores и Git-состояние. Старый результат теста не является доказательством нового кода.

## Граф и поиск

```bash
python3 scripts/development_memory.py --root PROJECT link component architecture depends_on --evidence .project-master/ARCHITECTURE.md
python3 scripts/development_memory.py --root PROJECT index
python3 scripts/development_memory.py --root PROJECT search 'invoice retry' --limit 5
```

Сначала зарегистрируй оба ID. Типы связей: depends_on, implements, verifies, constrains, supersedes. Evidence должен действительно обосновывать связь; инструмент проверяет наличие/hash, но не истинность утверждения. Не превращай гипотезу в подтвержденную зависимость. При изменении evidence связь исключается до повторного рассмотрения.

Индекс обрабатывает только явно зарегистрированные UTF-8 файлы до 1 MiB; никаких автоматических сканирований репозитория, секретов, сырых логов или переписки. Перед register проверь содержимое: технический фильтр путей не заменяет проверку персональных данных. Индекс обновляет embeddings только измененных sources. SQLite FTS5 обеспечивает точный поиск; при отсутствии/повреждении индекса работает файловый fallback. Индекс можно пересоздать. Не редактируй registry вручную; lock после сбоя проверяется по PID, не удаляется автоматически.

## Архив

```bash
python3 scripts/development_memory.py --root PROJECT close attempt-1 --outcome failed
python3 scripts/development_memory.py --root PROJECT archive attempt-1 --lesson 'Повторная доставка удваивала платеж; вернуться только после idempotency key'
python3 scripts/development_memory.py --root PROJECT restore attempt-1
```

Архивируются только закрытые failed/rejected записи kind=experiment. Падающие регрессионные тесты и нерешенные дефекты не являются экспериментами. Активные evidence-ссылки графа блокируют архивирование. Проверь также ссылки вне графа: автоматический анализ всех документов не выполняется. Физические файлы не перемещаются и не удаляются. Краткий отрицательный урок остается в восстановлении. Тела архива исключены из обычного поиска; `search --include-archive` применяй только с конкретной причиной пересмотра.

В конце каждого компонента и когда сводка превышает бюджет проверяй закрытые эксперименты и архивируй подходящие записи. Возраст сам по себе не основание. Это часть execution loop, без фонового расписания.

## Локальные векторы

Ядро не требует сторонних библиотек. Для семантики отдельно установи `fastembed==0.7.4` в выделенное virtualenv. ONNX multilingual модель требует диска и памяти; runtime не устанавливает зависимости самостоятельно. Загрузка модели разрешается один раз явно, проектный текст обрабатывается локально:

```bash
export PM_EMBEDDING_CACHE=/absolute/private/model-cache
PM_EMBEDDING_DOWNLOAD=1 python scripts/development_memory.py --root PROJECT index --semantic
python scripts/development_memory.py --root PROJECT search 'защита от повторной оплаты' --semantic
```

Без download-флага используется только локальный cache. Векторная идентичность включает название модели, размерность 384 и версию разбиения. Индекс с несовместимой моделью не используется для cosine. Модель — paraphrase-multilingual-MiniLM-L12-v2. При отсутствии движка semantic search честно переходит к тексту; semantic index завершается ошибкой, не обещает созданные векторы.

## Бюджет

3000 — мягкий начальный бюджет, оценка `ceil(JSON characters / 3)`, не точный tokenizer и не размер всего окна модели. Обязательный core, архитектурные/decision summaries и отрицательные уроки не теряются при переполнении; `budget_exceeded` виден. Второстепенные источники перечисляются в `omitted`. При большом обязательном ядре пересмотри формулировки и актуальность решений, не скрывай ограничения.

Не перечитывай в одной сессии неизмененные источники; перед мутацией проверь относящиеся к ней файлы. Ищи 3–5 фрагментов, расширяй только при недостаточности. Не логируй каждую команду, не повторяй полные отчеты тестов. Сначала сводка, затем исходники по ссылкам. Модель/effort не переключаются этим механизмом. Экономию сравнивай на одинаковом корпусе и задаче по объему контекста и качеству ответа; не выдавай оценку контекста за фактический биллинг.
